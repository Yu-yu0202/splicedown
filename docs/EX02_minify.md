# EX02: minify の動作と検証

minify は、展開する依存クレートの選択と、rustc の `dead_code` 診断を使う項目単位の削除を行います。削除後のソースはコンパイラで再検証します。

## 依存クレートの選択

通常の minify では、エントリとそこから参照する依存のソースを順に調べ、到達するクレートだけを展開します。ローカルモジュール、依存の別名、マクロ内のトークンも対象です。選択後の検証に失敗した場合は、全依存を含むバンドルで再試行します。

`--no-minify` では従来どおり全依存を展開します。`--no-minify --minify-test` も依存の選択は変えず、テストコードの削除だけを有効にします。依存グラフの取得と Edition 2024 の検査は選択前に行います。

## 項目の削除

診断のソース位置と構文木の位置を照合するため、別モジュールに同名の関数や定数があっても区別できます。通常の関数・定数・型などに加え、inherent impl 内の未使用メソッドと関連定数も対象です。trait impl や副作用を持つ可能性のある属性は保守的に扱います。

候補をまとめて削除し、検証に失敗した集合だけを分割します。削除できない項目があっても、ほかの候補を引き続き試します。成功したソースから診断を取り直し、追加の削除がなくなるまで繰り返します。未対応の構文やマクロ展開で生成された項目まで完全に削除する保証はありません。

## コンパイラとキャッシュ

診断の取得には `cargo rustc --profile check -- --force-warn=dead_code` を使います。フラグを生成バイナリだけに適用することで、外部依存を minify 用と最終検証用に二重コンパイルすることを避けます。最後は通常の lint 設定で `cargo check` を行い、`deny(dead_code)` などの設定も確認します。

検証用ディレクトリごとに固有の bin 名を使い、共有 `CARGO_TARGET_DIR` でも別の生成ソースの検証結果を再利用しないようにします。外部依存のコンパイル成果物は共有できます。

`--no-check` は最終チェックを省くオプションです。minify 内部の安全性検証は省きません。すべての生成ソース検証を省く場合は `--no-minify --no-check` を使います。

参考: [Cargo の cargo rustc](https://doc.rust-lang.org/cargo/commands/cargo-rustc.html)、[rustc の lint levels](https://doc.rust-lang.org/rustc/lints/levels.html)。
